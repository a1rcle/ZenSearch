# ZenSearch 路径注入（Quick Switch）系统设计规范

> **模块定位**：ZenSearch 核心功能之一，在系统通用文件对话框（`#32770`）中实现目录快速切换。  
> **技术栈**：Rust 2021、Win32 API、UI Automation、COM。  
> **关联源码**：`src/core/injector.rs`、`src/core/explorer.rs`、`src/core/hotkey.rs`。  
> **架构文档**：[architecture.md](file:///d:/ZenSearch/docs/architecture.md)

---

## 一、 交互规范与双模支持

路径注入支持两种协同触发模式：

1. **切回自动跳转（主模式）**：
   用户在资源管理器浏览或选中目标目录后，直接切回（点击或 `Alt+Tab`）文件对话框，对话框自动重定向至该路径。点击对话框任意区域（文件列表空白处、导航栏、地址栏或底部输入区）均可平滑触发，无需按键。
2. **`Ctrl + G` 手动跳转（辅助模式）**：
   在分屏等两窗口并存场景下，用户无需切换前台焦点，直接在文件对话框内按下 `Ctrl + G` 即可原地拉取最新路径。

## 二、 架构与状态流转

### 1. 核心设计原则
* **严格 MRU 定向 (Strict MRU Policy)**：系统仅跟踪最近一次激活的资源管理器窗口（`CabinetWClass`）。若该窗口已关闭或不存在有效记录，保持静默，绝不进行后台窗口遍历猜测，防止篡改对话框默认路径。
* **转移链路约束 (Focus Transition Guard)**：仅当前台焦点从“有效资源管理器窗口”切换至“文件对话框（`#32770`）”时执行自动注入；从浏览器、文本编辑器等非资源管理器应用切入时不触发。
* **幂等防护**：若对话框当前路径已是目标路径，直接跳过注入，避免重复刷新造成焦点闪烁。

### 2. 执行流转全景

```
[ 资源管理器激活 ] ──(EVENT_SYSTEM_FOREGROUND)──> 更新 FocusTracker (HWND / 路径)
         │
         ▼ (切回文件对话框: 点击任意区域 / Alt+Tab)
[ 对话框获得焦点 ]
         │
         ├── 链路检查: 上一前台窗口是否为有效资源管理器? ──[否]──> 保持静默
         │
         └── [是] 进入注入流程:
               1. 备份文件名: 读取并暂存当前 Edit 原始文件名（过滤路径片段）
               2. 点击时序同步: 等待鼠标按键物理释放及子控件焦点事件结算
               3. 焦点锁定: AttachThreadInput + SetFocus 将焦点强置于文件名 Edit
               4. 路径注入: 填入规范化路径 (强制附加尾部反斜杠 "\") 并发送 VK_RETURN
               5. 状态校验与自愈: 校验地址栏 (ToolbarWindow32) 实际路径，必要时重试
               6. 文件名复原: 还原原文件名并保留输入焦点
```

## 三、 关键实现机制

### 1. 焦点监听与状态维护 (`FocusTracker`)
使用 `SetWinEventHook` 监听 `EVENT_SYSTEM_FOREGROUND` 事件，在全局单例中维护焦点转移历史：

```rust
pub struct FocusTracker {
    pub last_explorer_hwnd: Option<isize>,
    pub last_explorer_path: Option<String>,
    pub prev_foreground_hwnd: Option<isize>,
}
```

### 2. 对话框控件寻址与定位
递归遍历 `#32770` 对话框控件树，定位实际的文件名编辑框：
* **定位链路**：`ComboBoxEx32` $\to$ `ComboBox` $\to$ `Edit`（优先匹配标准控件 ID `0x47c / 1148`、`1001`、`1152`）。
* **排除规则**：显式忽略搜索框（`SearchEditBoxWrapperClass`）与地址栏隐藏编辑框（ID `41477`）。
* **可用性检查**：结合 `IsWindowVisible` 与 `IsWindowEnabled` 确保目标控件有效。

### 3. 输入同步与焦点调度
在对话框内点击不同区域（文件列表视图 `DirectUIHWND`、导航树 `SysTreeView32`）会导致键盘焦点被子控件捕获。系统采用以下机制保证注入可靠性：
* **鼠标释放等待 (`wait_for_mouse_release`)**：轮询检测 `VK_LBUTTON` 物理释放并附加缓冲窗口，确保宿主程序处理完点击与选区逻辑。
* **跨线程焦点强锁 (`focus_dialog_edit`)**：通过 `AttachThreadInput` 附加对话框线程，调用 `SetFocus(edit_hwnd)` 强制将键盘焦点重置到文件名输入框，同时收起可能处于展开态的顶部地址栏。
* **路径注入与回车驱动**：向目标 `Edit` 写入标准化路径，再通过原生 `VK_RETURN` 激发对话框内置的目录切换状态机。
* **地址栏回环校验**：通过读取 `ToolbarWindow32` 的面包屑文本校验实际物理路径，在未完成切换时执行自愈重试。

### 4. 平台兼容设计
* **Windows 11 多标签页支持**：结合 `IUIAutomation` 与 `IShellWindows`，精确定位当前激活 Tab 对应的物理路径。
* **UIPI 权限穿透**：通过高权限计划任务启动并常驻，确保能够正常向管理员权限运行的应用程序对话框发送 Win32 消息。

## 四、 边界处理与容错矩阵

| 场景 | 触发条件 | 系统行为与保护策略 |
| :--- | :--- | :--- |
| **非资源管理器切入** | 前台来源非 `CabinetWClass` | **安全静默**：不执行注入，保护用户正在选择的文件。 |
| **源窗口失效** | 目标资源管理器句柄已关闭 | **安全静默**：失效即刻作废，不进行盲目回退。 |
| **路径幂等** | 对话框已处于目标目录 | **跳过注入**：幂等忽略，防止界面闪烁。 |
| **高频切换** | 快速重复触发焦点事件 (< 300ms) | **防抖去重**：忽略重复事件，避免竞态。 |
| **子控件夺焦** | 点击空白处或导航树 | **输入同步与强锁**：等待鼠标释放后跨线程强锁焦点至 Edit。 |
| **路径语法歧义** | 目标路径未带分隔符 | **路径规范化**：末尾附加反斜杠（如 `D:\TargetDir\`），防止被作为文件名解析。 |
| **文件名保护** | 输入框中存在待存文件名 | **备份与还原**：注入前暂存，跳转成功后即刻复原。 |
| **状态确认** | 注入指令发出 | **回环校验**：以读取到的 `ToolbarWindow32` 物理路径作为完成判定标准。 |
